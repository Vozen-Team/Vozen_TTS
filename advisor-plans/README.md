- Caller-supplied `X-Forwarded-For` was not planned as a vulnerability: the runtime binds the API
  to loopback and the deployment documents a single trusted proxy boundary.
- TTS/cache and rejoin “unbounded growth” findings were rejected because eviction and bounded
  batches are present in the current Rust implementation.
- Existing `plans/` entries are legacy TypeScript plans and are not duplicated here.
- Plan 012's historical inventory is not a remediation: the 2026-08-19 audit
  found advisory-bearing production dependency paths, which are tracked in
  Plan 017.

## How to execute these plans (read this first)

- **Worktree / branch**: all twelve plans land on ONE branch,
  `fix/tts-audit-bugs-20261125`, created from `origin/migration/vozen-rust`, in the
  worktree `C:/Users/diogo/.codex/worktrees/vozen-voice-language-engines/Vozen-audit`.
  One commit per plan, in the order below. Do not create other branches.
- **No push, no PR, no deploy.** Stop after the last commit. The repository owner
  pushes and opens the PR.
- **Commit messages**: imperative English sentence, no prefix, no trailer, matching
  `git log` (e.g. `Localize the Vozen TTS voice setup panel`). Never add
  `Co-Authored-By`, "Generated with" or any AI attribution line.
- **Rust gates run in Docker**, because Windows App Control blocks locally built
  test binaries. From Git Bash at the worktree root:

  | Purpose                     | Command                                                                      | Expected                       |
  | --------------------------- | ---------------------------------------------------------------------------- | ------------------------------ |
  | Targeted tests              | `bash advisor-plans/docker-check.sh cargo test -p <crate> <filter> --locked` | `test result: ok`, 0 failed    |
  | Full gate (after each plan) | `bash advisor-plans/docker-check.sh gate`                                    | last line `== GATE OK`, exit 0 |
  | Contracts (host)            | `node tools/check-rust-contracts.mjs`                                        | exit 0                         |
  | Canaries (host)             | `node tools/check-rust-canaries.mjs`                                         | exit 0                         |

  The first `gate` run in a fresh target volume takes 10–20 minutes; run it in the
  background. `npm run format:check` already fails on `c1dd4a9` for 9 files no plan
  touches (`PRIVACY.md`, `tools/cf-security-headers.mjs`, vendored metadata...);
  do not "fix" them and do not treat that failure as yours.

- **Line numbers** in the plans refer to commit `c1dd4a9`. Each plan starts with a
  drift check; earlier plans in this series shift lines in shared files
  (`core_voice_sink.rs`, `voice_playback.rs`), so search by the quoted code, not by
  line number alone.
- **Tests**: every Rust file named in the plans has a `#[cfg(test)] mod tests` at
  the bottom; add new tests there unless the plan says otherwise, modelled on the
  closest existing test in the same module.
- **Never edit an existing test's expectation to make a plan pass.** If an existing
  test asserts the behaviour a plan changes, STOP that plan, mark it BLOCKED with the
  test name, and continue with the next plan.
- **Formatting of these files**: after editing any `advisor-plans/*.md` (e.g. a
  status row), run
  `node node_modules/prettier/bin/prettier.cjs --write advisor-plans/README.md advisor-plans/0{19..30}-*.md`
  (run `npm ci --ignore-scripts` once first if `node_modules` is missing).
- **BLOCKED is allowed**: if a plan hits a STOP condition, mark it
  `BLOCKED (<reason>)`, revert its uncommitted code changes
  (`git checkout -- <files>`), commit only the README status row, and continue with
  the next plan whose dependencies are DONE.

## Findings considered and rejected (2026-11-25)

- Game-thread deletion deleting a real channel: not possible, `parent_channel_id`
  is `None` when the game runs in the command's own channel.

- Cross-user clicks on randomizer/cast panels: those panels are ephemeral.
- WAV size overflow, SQLite `busy_timeout`, `INSERT OR REPLACE` misuse, gTTS retry
  bounds: checked and clean.
- Dashboard guild authorization, admin sessions, Stripe signature/idempotency,
  plan-change tokens, Ko-fi claims, Google quota reservation: checked and clean.
- Setup-complete Test/Diagnose buttons answering "Run /setup again" after 15
  minutes: not planned. They are admin-only by design (test at
  `setup_wizard.rs:1292`) and still answer; low value.
